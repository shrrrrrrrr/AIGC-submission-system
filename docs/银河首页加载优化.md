# 银河首页加载优化

本次只调整首页资源传输、下载顺序、初始化计算和进入体验。原始点云、五个银河预设、着色器、DPR、泛光、相机取景与交互参数均未修改。登录、投稿、人员介绍、管理员接口及数据库不在本次改动范围内。

后续按用户要求单独调整了银河 C 的电脑端取景：宽度不小于 700 像素时按屏幕比例放大铺满，允许裁去画面边缘，并同步更新 C 的桌面和超宽屏静态预览。该项取景调整是前述加载优化之后的独立修改；手机端和其他四个银河取景保持不变，点云数据不变。

再次微调：银河 C 相对首次铺满版本缩小约 10%。五个银河在最后的画面输出阶段统一增加亮度和饱和度（亮度曲线系数 1.2、饱和度系数 1.18，保留黑白端点），不修改辉光强度、半径、阈值或辉光输入。三种尺寸的 15 张静态预览均同步重新渲染。这些颜色调整只作用于银河背景，不作用于网页文字和开屏星空图。

## 优化内容

- 使用用户提供的蓝色星空图 `web/public/assets/galaxy-opening.png` 铺满开屏，中央显示实际百分比、进度条和 `loading……`，沿用得意黑字体。开屏从组件出现时计时，包含淡出动画，目标上限为 5 秒；首屏动态银河提前就绪则提前进入。Escape 可提前进入，退出时恢复滚动和键盘焦点。
- 进度来自点云响应实际收到的字节，每组内部按数据量加权，五组均分总进度。未知响应长度时在校验完成后更新；全部五组完成 GPU 准备前不显示 100%。达到时间上限直接进入，不伪装为已全部加载完成。
- 提前下载五组静态预览，动态版本未就绪时显示这些图片。静态预览直接由正式渲染器、原有点云和认可参数渲染，手机、桌面、超宽屏共 15 张 WebP，位置为 `web/public/galaxy/previews/`。修改银河参数后应同步更新预览。WebGL 不可用时仍能显示静态背景。
- 优先准备可见章节，最多同时准备两组，然后逐组准备其余银河。编译着色器、上传缓冲区、离屏预热并实际绘制后，才淡出该章节静态图。
- 五组准备好后在本次首页浏览期间全部保留，往回滚动不下载、不重新创建点云或 GPU 缓冲区。只绘制可见章节；离开首页才取消请求、释放资源、移除监听。内存占用会高于原先只保留相邻章节，但仍共用一套后处理渲染目标。
- 资讯图片在胶卷进入视口前 300 像素开始下载，避免首次打开时抢占银河带宽。
- 元数据与预设并行加载；复用相同构图的计算结果，避免每次调整窗口尺寸都重复排序。点属性拆分直接写入数组，减少临时对象。
- 生产构建自动生成 35 个 `.bin.gz` 无损传输副本，原始 `.bin` 保留。客户端解压后使用完全相同的浮点数据。不支持解压、资源缺失或压缩损坏时自动读取原始文件。

## 本地验证（2026-10-01）

生产静态预览、Chromium、1440×900、禁用缓存、10 Mbps 下载带宽、80 ms 模拟延迟：开屏持续约 4.72 秒，退出时五组静态图均已加载；动态资源在后台继续准备。五组准备完成后往返滚动，各点云仍只请求一次，共 35 次，无页面脚本错误。手机点云下载失败时也在上限内进入并显示静态背景，无横向溢出；请求停滞场景开屏约 4.79 秒退出。无 WebGL、Escape 跳过、开屏期间切换到登录页的遮罩及滚动锁清理均通过验证。

上限针对开屏组件出现后的等待，不代表任何网络和设备都能在 5 秒内下载全部动态资源；浏览器主线程阻塞、页面挂起也可能影响计时器执行。下面为此前仅优化动态加载的测量，起点为页面导航，终点为首屏银河完整绘制：

| 阶段 | 首屏银河就绪 |
| --- | ---: |
| 优化前 | 16.139 秒 |
| 首屏优先与备用图按需加载 | 10.213 秒 |
| 传输与初始化优化后 | 7.717 秒 |

此前动态绘制等待减少约 52%；现在通过静态先呈现、动态就绪替换，避免用户在章节间等待。这不是线上测速承诺，服务器带宽、网络、设备与缓存都会影响实际时间。

35 个原始点云总计 34,670,528 字节，传输副本总计 29,614,432 字节，减少约 14.6%。全部副本解压后逐字节匹配原始文件。优化前后五个银河的所有顶点属性哈希，以及 390×844、1440×900、1920×1080、2560×1080 的构图范围和相机投影完全一致。

运行 `npm run test:galaxy` 可重建生产资源并检查优先级、双银河调度、并发限制、五组保留与往返复用、失败后继续加载其他章节、真实字节进度，以及压缩文件和静态预览的完整性。临时浏览器脚本、测量记录与截图位于本地忽略目录 `.tmp-verification/`，不包含真实投稿数据。

## 预览与后续部署

本地生产预览入口：`http://127.0.0.1:5175/#home`。5173 开发预览也包含调度和计算优化，但无损传输副本在生产构建时生成，应使用 5175 验收完整效果。

Git 提交与推送不代表已部署服务器。后续发布仍使用现有流程，完整发布 `web/dist/`（包含开屏背景、静态预览、新增 `.bin.gz` 和保留的 `.bin`），银河部分无需新服务、端口、数据库或服务器配置；投稿汇总表涉及的后端需按其说明同步发布。不应只发布 JavaScript 而遗漏静态资源。回滚使用此前完整前端构建即可。
