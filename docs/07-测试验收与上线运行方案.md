# ChinaVR 2026 AI、VR影像单元投稿系统｜测试验收与上线运行方案

> 本文定义开发完成的证据、上线门槛和故障处置。它是设计方案，不代表已经执行过测试；开发阶段必须产出可复现的测试记录和实际结果。

## 1. 验收原则

- 每项上线结论必须有新鲜、可复现的证据：测试报告、监控截图/链接、恢复演练记录或审计样例。
- 以“参赛者可完成链接投稿、组委会可安全处理作品”为主线；UI 截图不能替代权限、状态机、链接预检和恢复测试。
- 高风险问题（数据泄露、越权访问、SSRF、可绕过投稿规则、不可恢复）为阻断项；低风险文案或视觉问题可登记后修复。
- 测试环境只使用模拟或脱敏数据、受控测试链接、虚构账号和密钥；不提交真实参赛作品或生产联系方式。

## 2. 测试分层与责任

| 层级 | 目标 | 最低覆盖内容 | 责任人 |
| --- | --- | --- | --- |
| 单元测试 | 规则在最小范围正确 | 分数计算、状态迁移、字段校验、URL 解析、用途/时长/分辨率规则、权限判定 | 开发 |
| 集成测试 | 服务、数据库、队列、平台适配正确协作 | 事务、幂等、预检回调、会话撤销、审计落库 | 开发 |
| 端到端测试 | 用户真实路径可完成 | 注册、草稿、链接检测、失败定位、提交、退回补充、评分、受控外链打开 | 开发 + 测试 |
| 安全测试 | 常见攻击不能绕过 | 认证、越权、CSRF、SSRF、链接预检绕过、限流、依赖漏洞 | 开发 + 安全复核 |
| 性能与恢复 | 在赛事规模下稳定、可恢复 | 并发检测、队列积压、备份恢复、回滚 | 运维 + 测试 |
| 业务验收 | 规则与组织流程吻合 | 赛事文案、链接规则、角色、评分、通知、导出 | 组委会代表 |

| E2E-12 | 异步导出 | 字段受白名单限制，导出受控并记录 | 导出任务记录 |

## 4. 安全验证清单

- 身份认证：错误账号与错误密码返回一致；登录、重置密码和 MFA 均按账号/IP 限速；退出与重置密码撤销会话。
- 授权：替换投稿 ID、链接 ID、评审 ID 为他人 ID，必须收到 `403` 或不泄露式 `404`；前端隐藏操作不作为授权依据。
- CSRF/XSS：所有 Cookie 写接口进行 CSRF 验证；用户输入、评语、导出内容按上下文编码；CSP 不允许任意第三方脚本。
- SSRF：覆盖字面量/编码私网 IP、IPv6、DNS 重绑定、环回/保留地址、带用户信息 URL、非标准端口、重定向链、大响应、慢响应与伪造平台 URL。全部不得产生对内网的请求，也不得返回第三方原始内容。
- 链接规则：仅经批准的平台适配器可通过；需要登录、已删除、区域受限或无法获取强制元数据的视频必须返回稳定失败码；不能以客户端篡改元数据绕过。
- 依赖和密钥：CI 对 lockfile 做漏洞扫描、秘密扫描和许可证检查；命中 CISA KEV 或高危已知漏洞的依赖不得发布，除非有书面风险接受和缓解措施。
- 审计：登录、权限变更、预检、提交、退回、外链打开、导出、评分锁定/解锁、配置修改均可按 `requestId` 追溯。

## 5. 性能、容量与可用性验证

以约 100 名用户为当前规模假设。建议测试至少覆盖：20 名用户并发登录与浏览、10 名用户同时发起/重试链接检测、5 名管理员/评审同时检索与评分、Worker 处理积压任务后的恢复。具体 SLO、RPO、RTO 由 Q-013 在上线前确认。

| 指标 | 建议目标 | 失败处理 |
| --- | --- | --- |
| 常规 API P95 | ≤ 800ms，不含异步预检等待 | 定位索引、缓存、慢查询或限流 |
| 草稿保存 P95 | ≤ 1.5s | 不通过则禁止上线 |
| 预检任务入队 | ≤ 3s | 检查队列、限流与幂等逻辑 |
| 预检完成 | 在平台适配器运营承诺时间内完成 | 排查出网、适配器、重试和熔断 |
| 登录/提交错误率 | 压测期间 < 1%（排除预期拒绝） | 不通过则修复或降级 |
| 备份恢复 | 在约定 RPO/RTO 内完成 | 不通过则阻断生产上线 |

## 6. 备份、恢复与回滚演练

1. 数据库误删/迁移失败：从最新备份恢复到隔离环境，校验用户、投稿版本、链接预检结果、评分、审计关系完整。
2. 链接预检 Worker 故障：停止 Worker 后恢复，验证队列任务不重复通知、不丢检测结果，失败任务可安全重试。
3. 平台适配器异常：熔断后不给出误通过结果；恢复后只重试仍可编辑、仍有效的任务。
4. 发布异常：回滚应用版本，验证现有会话、投稿版本和链接检测任务兼容性。
5. 凭据疑似泄露：撤销会话、轮换密钥、检查审计、保留取证日志。

演练记录最小字段：`演练编号、时间、参与人、故障模拟方式、备份版本、恢复步骤、实际 RPO、实际 RTO、数据校验结果、遗留问题、批准人`。

## 7. 上线门槛

- E2E-01 至 E2E-12 通过，或有经负责人签字的非阻断豁免。
- 高危/严重安全问题为 0；中危问题有修复计划、临时缓解和负责人。
- 数据库迁移已在测试环境验证，有备份和回滚路径。
- 允许平台配置、隔离预检 Worker、SSRF 防护、管理员 MFA、审计日志和告警均已验证。
- 已完成至少一次数据库、链接预检元数据和版本快照恢复演练。
- 赛事正式内容、联系方式、截止时间、平台范围等配置已由《待核实问题清单》确认。
- 生产密钥、域名、HTTPS、通知配置和出网策略已注入且未出现在代码、日志和构建产物中。
- 同机其他项目隔离验证通过，不共享数据库、目录、端口、出网身份或可写密钥。

## 8. 上线日运行清单

- 上线前：确认备份成功、监控面板与告警接收人有效；用测试账号从赛事主页点击“立即投稿”，完成一条受控测试链接的预检与提交，随后撤回/清理测试稿。
- 上线后 24 小时：观察登录失败、链接预检失败、适配器积压、外链打开量、错误率和数据库连接；核对截止时区与邮件链接。
- 截止日前后：提前公布截止时间和维护窗口；截止时按配置关闭提交，保留已提交稿件查询和管理端审查；公布链接过期、平台故障和人工申诉的处理规则。

## 9. 故障分级与响应

| 级别 | 例子 | 首要动作 | 升级标准 |
| --- | --- | --- | --- |
| P0 | 数据泄露、全站不可用、SSRF 触及内网 | 停止受影响入口、保全日志、通知负责人 | 立即，启动安全响应 |
| P1 | 无法提交、链接预检大面积失败 | 降级非核心功能、熔断适配器、修复或回滚 | 30 分钟内无法恢复 |
| P2 | 单项管理功能异常、部分通知失败 | 建工单、重试、人工补偿 | 影响扩大或临近截止 |
| P3 | 文案、非核心视觉、低频体验问题 | 登记后排期修复 | 无需紧急升级 |

正式联系人、响应时限和外部沟通口径由 Q-008/Q-011/Q-013 统一确认。
