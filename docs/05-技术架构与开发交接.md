# ChinaVR 2026 AI、VR影像单元投稿系统｜技术架构与开发交接

## 1. 架构结论

一期采用模块化单体 Web 应用：公开赛事主页、独立投稿页、参赛者中心和管理评审端共享一套后端与数据库。参赛视频不进入本站；异步 Worker 只通过隔离的出网通道和经批准的视频平台适配器核验链接，另负责通知和导出。这适合约 100 名用户，边界清楚，也保留后续拆分能力。

```text
浏览器
  ├─ 赛事主页 ──“立即投稿”──► 独立投稿页 / 参赛者中心 / 管理评审端
  │                                  │ HTTPS + 服务端会话 Cookie
  ▼                                  ▼
反向代理 ── Web 应用（认证、投稿、评审、管理 API） ── PostgreSQL/MySQL
                   │                              │
                   │                              └── Redis（会话、限流、异步队列）
                   └── 链接预检 Worker（隔离出网、平台适配器、通知、导出）
                                  │ 仅限认可平台 API/元数据端点
                                  ▼
                           公共视频平台
```

## 2. 推荐技术边界

| 层 | 责任 | 约束 |
| --- | --- | --- |
| 前端 | 赛事主页、独立投稿页、分步表单、逐条预检结果、无障碍 | 不保存长期访问令牌；不直接请求用户输入的 URL |
| 后端 API | 认证、权限、状态机、业务校验、预检任务、审计 | 所有输入服务端复验；统一错误和请求 ID |
| 数据库 | 业务事实、版本快照、链接预检结果、评分、审计 | 事务保证提交/状态迁移原子性；备份可恢复 |
| 链接预检 Worker | 安全 URL 验证、平台适配、受限元数据获取、通知、导出 | 独立网络策略；任务幂等、可重试、死信队列和告警 |
| 运维 | 发布、日志、监控、备份、密钥、出网策略 | 与同机项目隔离，密钥不进仓库或日志 |

具体框架（如 Next.js/NestJS、React/Vue、PostgreSQL/MySQL）留到开发启动时按团队能力选定；接口合同、数据边界和安全基线不依赖该选择。

## 3. 模块划分

1. `identity`：注册、验证、登录、服务端会话、MFA、密码重置、角色。
2. `profile-team`：参赛者与团队资料。
3. `submission`：草稿、版本、六步校验、回执、状态机。
4. `media-link`：URL 规范化、平台白名单、预检任务、元数据、失败规则、受控打开。
5. `review`：资格审查、分配、评分、反馈。
6. `admin`：筛选、导出、赛事配置、用户与权限管理。
7. `notification`：站内通知和可替换的邮件/短信通道。
8. `audit-observability`：审计、请求 ID、错误追踪、指标和告警。

模块间只通过服务层和明确的数据访问接口协作；禁止管理端绕过状态机直接修改作品记录。

## 4. 核心数据与事务边界

- 创建投稿草稿：创建 `submission` 与第一个可编辑版本，事务内生成不可猜测 ID 和回执候选号。
- 保存/预检链接：校验当前草稿归属与 URL 基础规则；用 `Idempotency-Key` 创建唯一检测任务。Worker 只保存安全化结果，不保存第三方 HTML、Cookie 或原始响应。
- 正式提交：在一个事务中重新确认所有必填字段、声明和必填链接的 `passed` 结果仍有效，锁定版本、写入状态事件、创建通知任务。
- 状态迁移：校验角色、对象归属、允许迁移表和原因；在一个事务中更新当前状态、写入历史和审计。
- 评分提交：校验四维度范围与总分；按“评审人 + 投稿版本”唯一约束保存，避免并发重复评分。

## 5. 链接预检时序

1. 参赛者在独立投稿页输入链接并选择用途；前端只做格式提示，不能宣布合格。
2. 后端用可信 URL 解析器规范化地址，要求 HTTPS、允许的主机和端口；拒绝用户信息、字面量 IP、私网/环回/保留地址和不允许的重定向。
3. 后端创建可重试的异步任务，投稿显示“检测中”。
4. Worker 在独立受限网络中再次解析 DNS 和目标 IP；仅调用相应平台适配器/API，限制请求方法、响应大小、超时和重试，不进行任意网页抓取。
5. 适配器产出最小元数据：平台、外部视频 ID、无需登录可访问状态、时长、可获取的分辨率。无法可靠取得强制元数据即标记 `failed`，错误码为 `METADATA_UNAVAILABLE`。
6. 规则引擎按用途核对：主体作品 2—10 分钟且至少 1920×1080；制作解析不超过 1 分钟；VR/交互/实时导览视频为 1—5 分钟。将每条失败规则保存并安全返回。
7. 所有必填链接 `passed` 后状态才可为 `ready`。管理员/评审在授权详情页点击“在视频平台打开”时写审计记录，再返回此前核验过的规范化 URL；不支持本站下载原件。

官方片头、AI 占比、版权、生成内容标识不能仅凭链接自动证明。它们由强制声明/说明字段收集，并在资格审查中人工核验，不能被预检结果替代。

## 6. 认证与安全决策

### 当前安全态势（2026-09-22）

认证方案以 NIST SP 800-63B-4 和 OWASP 当前指南为规范上限：密码用 Argon2id、允许长密码和 Unicode、无强制组合规则、使用泄露密码拦截；单域 Web 应用采用服务端会话更容易立即注销和撤销。近期 CISA KEV 仍包含认证绕过和 CSRF 等被实际利用的问题，因此必须锁定依赖、审查生命周期脚本、使用密钥扫描和最小权限。管理员与评审默认强制 MFA，优先 Passkey/WebAuthn，TOTP 仅作可用性后备。

外部链接预检是 SSRF 攻击面。OWASP API7:2023 与 SSRF 防护指南均要求严格来源/协议/端口白名单、禁用或逐跳重验重定向，以及网络层阻断内网地址和 DNS 重绑定。因此本系统不能以通用 `fetch(url)` 实现预检，必须用隔离 Worker 和平台适配器。

- 密码：Argon2id，参数以部署资源压测后固定；不记录密码或重置令牌；密码重置令牌只存哈希并一次性使用。
- 会话：服务端存储，登录和权限升级时轮换，退出/重置密码时撤销；Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Lax` 或更严格值；所有写操作配合 CSRF 防护。
- 权限：RBAC + 对象级授权 + 状态检查；后台和评审账号强制 MFA、短会话、敏感动作再认证。
- 链接：严格平台白名单、可信 URL 解析、DNS/IP 双重检查、隔离出网、响应上限和超时；日志清除 URL 查询敏感部分、Cookie、Authorization 和第三方响应正文。
- 依赖：提交 lockfile；CI 执行依赖漏洞扫描和秘密扫描；升级命中 KEV/高危公告的组件优先级最高。

## 7. 环境与发布

| 环境 | 用途 | 数据原则 |
| --- | --- | --- |
| 本地 | 开发与单元测试 | 仅虚构数据；链接适配器使用本地 stub，不访问外网 |
| 测试 | 集成、端到端、链接预检、权限验证 | 脱敏或模拟数据；只使用受控测试链接/模拟适配器 |
| 生产 | 正式投稿和评审 | 私有业务数据，备份、监控、审计与独立出网规则齐全 |

发布流程：代码审查 → 自动化测试和安全扫描 → 测试环境验收 → 数据库迁移预检和备份 → 生产发布 → 健康检查与回归 → 观察期。每个数据库迁移必须有备份和向后兼容/回滚说明；不允许直接在生产服务器手工改表。

## 8. 可观测性与恢复

- 指标：登录失败率、链接预检成功率/耗时、队列积压、平台适配失败、外部链接打开次数、状态迁移失败、数据库连接。
- 日志：结构化日志关联 `requestId`；保留管理与链接打开审计；按最小必要原则脱敏。
- 告警：登录暴力尝试、异常外部链接打开量、预检失败积压、平台适配器错误率、备份失败、应用健康检查失败。
- 恢复：数据库每日备份、链接预检元数据和版本快照定期恢复演练；记录实际 RPO/RTO，值由 Q-010/Q-013 确认后定稿。
