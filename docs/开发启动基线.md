# ChinaVR 2026 投稿系统｜开发启动基线

## 文档目的

本文件记录从设计交接进入代码开发时采用的事实、假设、首个纵向切片和验证门槛。它不替代 PRD、接口契约和上线方案；发生冲突时，以项目 `AGENTS.md`、需求基线、待核实问题清单和实现方案 PRD 的已确认结论为准。

## 已确认事实

- 本站接收公共视频平台链接，不接收、托管、下载或转码参赛视频。
- 一期以邮箱验证登录；手机号不是登录必填项。
- 管理员和评审账号需要 MFA；评审账号独立且彼此匿名。
- 主体作品链接、制作解析链接必须通过服务端预检；VR、交互和实时作品还必须提交导览视频链接。
- 预检必须使用平台白名单、HTTPS、DNS/IP 双检、隔离 Worker 和受控适配器，禁止通用 `fetch(url)`。
- 业务状态、版本快照、对象级授权和审计记录必须由服务端控制。
- 本地、测试、生产环境独立；不得把密钥、真实用户数据和真实投稿文件提交到仓库。

## 当前可逆假设

- 采用 Node.js + TypeScript 的模块化单体 Web 应用，HTTP 层使用 Hono，关系型数据库使用 PostgreSQL；具体 ORM 在数据库切片开始前写入 ADR，并通过锁定依赖固定版本。
- 本地预检使用 stub 适配器和虚构数据，不访问真实平台；正式平台清单由 Q-016 在投稿开放前确认。
- 先完成邮箱注册/验证、登录/退出、服务端会话、角色判定和审计闭环，再进入投稿草稿。
- 当前 Slice A 的内存仓储和邮件 stub 只用于本地/测试；生产启动工厂已接入 PostgreSQL 仓储选择、连接池生命周期和配置门禁，但在正式邮件适配器完成、迁移和真实数据库集成验证前仍会主动阻断。

## 首个纵向切片：Slice A（账号闭环）

### 范围

1. 注册请求和邮箱验证令牌流程。
2. 登录、退出、会话撤销和当前用户信息。
3. 参赛者、赛事管理员、超级管理员、评审专家四类角色的最小权限模型。
4. 管理员/评审 MFA 的接口边界和强制检查；当前先落地 TOTP 注册、加密密钥保存和验证码计数器防重放，Passkey 仍待资源评估。
5. 统一错误结构、请求 ID、登录限速和关键认证审计事件。

### 非范围

- 投稿编辑器、视频链接预检、评分、通知供应商和生产部署。
- 真实邮件供应商接入；本地与测试环境使用可检查的邮件捕获器或 stub。

### 必须验证的失败路径

- 注册、登录和找回密码不能泄露账号是否存在。
- 验证令牌和密码重置令牌一次性、过期后失效，数据库只保存令牌哈希。
- 登录失败按账号/IP 限速；退出和密码重置会撤销既有会话。
- 会话 Cookie 使用 `HttpOnly`、`Secure`、合适的 `SameSite` 和服务端过期时间；写操作有 CSRF 防护。
- 仅有对应角色、对象归属和当前状态同时满足时才允许敏感操作。
- 密码不进入日志、响应、审计详情或错误堆栈；联系方式按最小必要原则记录和展示。

## Slice A 当前交付与剩余项

已实现本地可验证闭环：注册/邮箱验证、Argon2id 密码、登录/退出、`__Host-` 会话 Cookie、CSRF、登录限流、审计、密码重置令牌、旧会话撤销、评审/管理员账号无 MFA 时拒绝登录，以及基于 TOTP 的 MFA 注册、AES-256-GCM 密钥密文保存和验证码计数器防重放。

尚未达到生产完成定义：PostgreSQL 仓储已接入生产启动工厂，但生产 MFA 密钥托管、受控的管理员/评审 MFA 初次注册运维流程、Passkey、正式邮件供应商、真实数据库迁移与集成验证尚未完成；内存仓储仍只用于本地测试。

## Slice B 当前进度

已建立前端原型：公开首页、投稿方向与准备说明、时间节点占位、登录入口和六步投稿编辑器的响应式界面骨架。服务端已增加内存投稿草稿 API，覆盖幂等创建、对象归属、`If-Match` 并发保护、链接待检测状态和基础 HTTPS/平台白名单校验。原型遵循“光场档案”视觉规范，日期、会场、Logo 和赛事配置仍使用可替换占位。

投稿 PostgreSQL 仓储和生产启动接线已完成本地契约测试，但尚未完成真实数据库集成验证；个人/团队资料、隔离链接预检 Worker、自动保存前端调用、完整状态机和正式提交接口仍未完成；当前前端保存按钮仍只用于验证交互结构，服务端 API 已可由后续接入使用。

## Slice A 验收证据

- 单元测试：密码策略、令牌生命周期、角色判定、限速决策、TOTP 注册和验证码重放拒绝。
- 集成测试：会话创建/撤销、验证令牌消费、审计落库、错误结构。
- 安全测试：账号枚举、CSRF、越权、重放令牌、Cookie 属性和敏感日志检查。
- 本地运行说明、锁定依赖清单、数据库迁移和回滚说明。

只有上述证据实际通过后，Slice A 才能标记完成；之后再进入 Slice B。
