# 投稿截止与通知

截止时刻固定为 **2026 年 10 月 20 日 24:00，北京时间**，对应 `2026-10-20T16:00:00Z`。服务端系统时钟为最终依据。上线前应检查服务器时间同步；不需要设置定时任务，也不需要数据库迁移。

- 截止前保留原投稿行为。
- 截止时及之后，参赛者新建稿件、修改草稿、修改链接、发起预检、正式提交均返回 `403 SUBMISSION_CLOSED`。已经打开的旧页面也受服务端限制。
- 校验在事务内进行，正式提交在取得配额锁后再检查一次，避免排队请求携带旧时间绕过截止。截止判断采用处理时的服务端时钟，不能由请求参数指定。
- 既有稿件、版本、回执、链接和草稿不清理、不迁移、不修改。参赛者仍能查看自己稿件；管理员查看、导出、审核和原权限/MFA/CSRF/审计规则保持不变。

## 页面通知

`GET /api/v1/submission-window` 公开返回截止时刻、服务器时间和截止状态，响应不缓存。网页以服务器时间和单调计时器计算状态，并在恢复页面、返回窗口及定期轮询时重新同步。首次无法确认状态时暂不允许写入，重试成功后恢复正常状态。

公开页面默认自动展示最新的“关于补充作品及创作团队信息的通知”，刷新、离开后返回也重新显示；不保存“已读后不再弹出”标记。首页开屏结束后再显示通知，避免两个弹窗争夺焦点。原后台页面不自动弹窗。截止状态轮询不会使已关闭的弹窗重新打开。

右上角的“通知”按钮始终可以打开通知列表，新公告排在首位；“投稿截止与评审安排”保留在第二位，仅在手动点击时展示，不再自动弹出。通知可用关闭按钮、我知道了或 Esc 关闭。只有打开旧截止公告时才读取本账号的投稿回执，新公告不读取个人稿件信息。

## 验证与上线

`npm test` 包含截止前一毫秒、截止瞬间、事务/配额锁跨截止、旧请求时间、所有投稿写接口拒绝、个人数据隔离、管理员查看及 CSV/XLSX 导出、MFA/CSRF、拒绝后数据不变与 PostgreSQL 事务回滚测试。旧有工作流测试固定在征集开放期，避免测试随实际日期失效。

首次关闭投稿必须同时发布后端与前端；只发布前端不能保证关闭投稿。后续补充信息公告只更新前端静态文件，保持已经上线的截止版 API 运行。没有新增环境变量、依赖、数据库字段或迁移脚本。部署操作脚本按要求单独交付、不进入 Git。部署前备份相关发行文件，沿用已有独立运行环境和服务；首次 API 升级还须备份数据库。不要重新初始化数据库、执行 down SQL、清空目录或把本地测试数据库上传到生产。

如果截止前部署，届时自动生效；如果截止后才部署，在新后端启动前旧服务仍可能接受投稿。旧后端回滚也会重新开放投稿，截止后应保留截止保护或暂时停止本项目 API，不能无条件回滚重启旧版本。生产环境的备份与发布尚需在服务器实际执行和验收。
