# ChinaVR 2026 AI VR影像单元 产品定义与核心流程

## 1 产品定位

本系统是 ChinaVR 2026 AI、VR影像单元的正式作品征集与评审平台，面向个人创作者、跨专业团队和学生征集 AI、VR、计算机图形学及数字影像作品。

系统的核心价值不是“收集一个视频文件”，而是建立一条可追溯的赛事链路：参赛者先将作品发布到公共视频平台，本站对链接和可自动核验的格式要求作严格预检，再组织资格审查和评分。

```text
赛事主页了解规则 → 进入独立投稿页 → 创建账户 → 提交并检测公开链接 → 正式提交 → 资格审查 → 专业评分 → 反馈与结果 → 展映归档
```

产品设计优先级如下：

1. 作品和个人信息安全。
2. 链接检测、保存、外部访问留痕和评分过程可靠。
3. 参赛者清楚知道当前状态和下一步动作。
4. 管理员可以高效、可追溯地完成审核。
5. 后续可以复用为其他正式比赛的投稿平台。

## 2 用户角色

| 角色 | 主要目标 | 核心权限 |
| --- | --- | --- |
| 访客 | 了解赛事并判断是否参赛 | 浏览公开内容、下载模板、查看时间和规则 |
| 参赛者 | 创建并提交个人或团队作品 | 注册、维护资料、创建草稿、提交并重新检测公开链接、提交、查看状态和反馈 |
| 评审专家 | 独立完成分配作品的专业评审 | 仅查看被分配作品、填写评分和评语、提交评审结果 |
| 赛事管理员 | 管理投稿和赛事流程 | 查看全部投稿、资格审查、分配评审、从受控详情页打开作品链接、退回补充、填写反馈、推进状态、导出数据 |
| 超级管理员 | 管理系统配置和权限 | 管理管理员/评审账号、配置赛事规则和截止时间、查看审计日志、执行数据恢复操作 |

评审专家和赛事管理员可以共用一套后台界面，但必须通过权限控制区分可见数据和可执行操作。参赛者只能访问与自己账号关联的作品。

## 3 产品目标与非目标

### 目标

- 支持完整的参赛者注册、投稿、公开视频链接预检和提交闭环。
- 对主体作品、制作解析和条件必填导览视频的外部链接做安全、可访问性、时长和分辨率等可核验项的预检。
- 支持资格审查、评分、反馈、结果通知和展映归档。
- 对所有关键动作保留时间、操作者、对象和结果记录。
- 在约 100 名用户规模下保持稳定，并能够恢复失败链接检测和中断操作。

### 一期非目标

- 在线报名缴费和发票系统。
- 面向公众的作品社区、评论和点赞。
- 自动识别 AI 生成比例、自动版权判定或自动评分。
- 复杂的多人实时协同编辑。
- 面向公众的高清视频 CDN 播放平台。

## 4 信息架构

### 公开端

- 首页：赛事定位、截止时间、重要入口。
- 赛事介绍：ChinaVR 2026 与 AI、VR影像单元说明。
- 投稿方向：前沿科技、中华优秀传统文化、科学幻想作品。
- 参赛规则：时长、格式、AI 使用、版权、标识和材料要求。
- 评审标准：四项评分维度、评分说明和流程。
- 时间安排：征稿截止、录用通知、现场展映。
- 资源下载：官方片头模板、说明模板、常见问题。
- 通知公告：组委会发布的更新和补充通知。
- 登录 / 注册：进入参赛者中心。

### 参赛者中心

- 我的作品：草稿、已提交作品、退回补充作品和历史版本。
- 新建投稿：分步填写作品信息、公开链接及声明。
- 投稿详情：链接清单、预检状态、提交时间、审核进度和反馈。
- 个人资料：姓名或团队名称、邮箱、学校、专业、指导教师等。
- 账户安全：修改密码、退出登录和登录异常提示。

### 管理端

- 工作台：投稿总量、待处理数量、评审进度和异常提醒。
- 投稿列表：按状态、方向、时间、创作者和关键词筛选。
- 资格审查：查看材料完整性、退回补充、记录审查意见。
- 评审任务：分配作品、查看评审完成度、处理冲突回避。
- 作品详情：受控打开外部作品链接、预检元数据、历史版本和操作记录。
- 评分与反馈：查看评分、填写管理员意见、形成最终结果。
- 公告与配置：管理通知、截止时间、规则文本和下载资源。
- 账号与权限：管理工作人员账号、角色和访问范围。
- 审计与导出：查看关键操作、导出脱敏数据和生成归档包。

## 5 核心用户流程

### 5.1 参赛者投稿

```text
访客浏览赛事主页
  → 点击“立即投稿”进入独立投稿页
  → 注册或登录
  → 创建作品草稿
  → 填写作品与主创信息
  → 填写主体作品、制作解析和条件必填导览视频的公开链接
  → 系统逐条预检安全性、平台可支持性、公开可访问性、时长、分辨率和完整性
  → 预览确认
  → 提交并生成投稿编号
  → 查看资格审查和评审状态
```

设计原则：链接检测可重试、可恢复；未完成草稿自动保存；任一必填链接未通过时必须显示具体不合格规则且禁止提交；提交前必须显示材料清单和声明确认；提交后生成不可变的投稿版本。

自动预检并不能证明作品实际使用了官方 3 秒片头、AI 占比、版权或生成内容标识。这些项目以强制声明和说明字段收集，并在“资格审查”由工作人员核验；“提交成功”仅表示所有可自动核验项通过且声明完整。

### 5.2 退回补充

```text
管理员发现材料问题
  → 选择问题类型并填写反馈
  → 作品状态变为“需补充”
  → 参赛者收到站内提示和邮件通知
  → 参赛者创建新版本并替换指定材料
  → 再次提交
  → 系统保留原版本和补充记录
```

提交后的作品不允许参赛者直接覆盖。只有管理员退回补充后，参赛者才能创建新版本，避免评审过程中材料被无痕替换。

### 5.3 评审流程

```text
投稿提交
  → 资格审查
  → 合格作品进入评审池
  → 分配评审专家
  → 独立评分和填写评语
  → 终评汇总
  → 管理员确认结果
  → 发布录用、入围或未入围通知
```

评审专家只能看到被分配的作品；是否隐藏作者信息、是否启用双盲评审，需要在下一阶段冻结。

## 6 投稿状态模型

| 状态 | 进入条件 | 参赛者可操作 | 管理端可操作 |
| --- | --- | --- | --- |
| 草稿 | 创建投稿或保存未完成材料 | 编辑、保存链接和声明 | 查看异常，不参与评审 |
| 链接检测中 | 对必填链接发起预检 | 等待、取消、重试 | 查看安全化检测状态 |
| 待提交 | 所有必填链接预检通过且声明完整 | 预览、确认提交 | 查看但不能评分 |
| 已提交 | 参赛者确认提交 | 查看，不可直接修改 | 开始资格审查 |
| 需补充 | 管理员退回 | 按反馈创建新版本 | 修改反馈并重新审查 |
| 资格通过 | 材料审查通过 | 查看状态 | 分配评审 |
| 评审中 | 已进入评审池 | 查看处理中 | 评分、评语、查看完成度 |
| 入围 / 获奖 | 终评确认结果 | 查看结果和后续说明 | 归档、展映授权管理 |
| 未入围 | 结果确认 | 查看结果和必要反馈 | 归档 |
| 撤回 / 作废 | 按规则处理 | 查看记录 | 记录原因，不物理删除审计数据 |

## 7 产品体验要求

- 每个页面都明确显示当前角色、作品状态和下一步动作。
- 链接区域显示平台、可访问状态、时长、分辨率、检测时间、具体失败规则和重试入口。
- 所有不可逆操作必须二次确认，并说明影响范围。
- 评分和反馈应支持自动保存，防止评审过程中断导致内容丢失。
- 错误提示必须说明原因和修复方式，不使用笼统的“提交失败”。
- 截止时间、时区和截止后的行为必须在公开端和投稿端保持一致。
