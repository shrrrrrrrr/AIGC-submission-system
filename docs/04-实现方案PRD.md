# ChinaVR 2026 AI、VR影像单元投稿系统

## 实现方案 PRD v0.1

> 文档用途：交给下一开发对话作为实现合同。本文只描述产品、交互、数据、接口、安全、部署和验收，不绑定具体前端框架或云产品 SDK。

## 1. 文档状态与决策边界

- **状态**：设计稿，开发前需完成“待确认项”评审。
- **事实来源**：项目级 `AGENTS.md`、已提供的《AI、VR影像单元》文档、参考站调研、`docs/00~03`。
- **已确认**：需支持注册登录、投稿信息填写、主体作品与制作解析的公开视频平台链接、条件必填的导览视频链接、自动预检、资格审查、评分和反馈；约 100 名用户；部署在已有阿里云服务器并与其他项目隔离。
- **设计假设**：一期采用单体 Web 应用 + 关系型数据库 + 隔离的外部链接预检 Worker；参赛者以邮箱登录，手机号作为待确认的可选扩展；本站不接收、托管、下载或转码参赛视频。
- **待确认**：统一登记于《待核实问题清单》；设计继续按其中“建议默认值”推进，开发启动前集中确认。

## 2. 产品目标

### 2.1 用户价值

让参赛者在一个可信、清晰、可恢复的流程中完成投稿；让组委会能按资格审查、初评、终评的阶段管理作品链接、记录评分和反馈，并保留完整审计证据。

### 2.2 一期范围

- 公开赛事信息、方向、规则、时间、FAQ、官方模板下载。
- 账号注册、登录、退出、忘记密码、个人资料。
- 个人/团队投稿，支持草稿保存、继续编辑、外部链接重新检测。
- 主体作品、制作解析、VR/交互补充导览视频的公共平台链接、可选体验链接和权利声明。
- 投稿确认、回执编号、状态查询、管理员退回补充。
- 管理员用户/作品检索、资格审查、受控打开已核验的外部链接、评分、反馈、导出。
- 审计日志、操作告警、备份和恢复演练所需的管理能力。

### 2.3 非目标

- 不做站内视频公开播放、社交点赞、在线剪辑、在线转码编辑器。
- 不在一期实现复杂的推荐算法、实时多人协作、支付、票务和移动原生 App。
- 不建设站内参赛视频上传、托管、下载、转码或播放能力；公开视频平台链接是唯一的作品交付方式。

## 3. 角色与权限

| 角色 | 核心权限 |
| --- | --- |
| 访客 | 浏览公开内容、下载公开模板、查看 FAQ |
| 参赛者 | 管理自己的账号、团队、草稿、提交版本；查看自己的状态、反馈和回执 |
| 评审专家 | 仅查看分配到的作品及必要链接；提交或修改自己的评分和评语；不可导出全量数据 |
| 赛事管理员 | 管理作品、资格审查、分配评审、受控打开外部链接、发送反馈、导出业务数据 |
| 超级管理员 | 管理账号、角色、赛事配置、备份恢复、审计日志和高风险操作 |

权限必须同时满足“角色权限 + 对象归属 + 当前状态”三项检查。任何外部链接打开、导出、退回、删除、修改评审结果的操作都写入审计日志。

## 4. 业务规则与状态机

### 4.1 投稿规则

1. 一名参赛者可创建多个草稿，但同一团队/作品名称的重复提交需要后台提示并由管理员确认。
2. 主作品时长 2–10 分钟；最低分辨率 1920×1080，建议 16:9。VR/交互/实时作品必须补充 1–5 分钟录屏或导览视频。
3. 核心视听内容原则上不低于 80% 为 AI 生成或深度辅助内容；必须填写工具、参与环节和人工贡献。
4. 必须提交不超过 1 分钟的制作解析，并声明素材、音乐、模型、数据、肖像等权利状况。
5. 提交后版本不可由参赛者静默覆盖；只有管理员执行“退回补充”才创建可编辑新版本，旧版本保留只读快照。
6. 主体作品与制作解析必须为组委会认可的公共视频平台链接；VR/交互/实时作品的导览视频也适用。所有必填链接必须同时通过安全 URL、允许平台、无需登录可访问、时长及可获取时的分辨率预检，否则提交失败并返回逐条规则。
7. 官方 3 秒片头、AI 占比/披露、权利与生成内容标识无法仅凭外部链接可靠证明。系统收集强制声明与说明，资格审查人工核验；自动预检通过不等于资格审查通过。

### 4.2 状态

`draft` 草稿 → `checking_links` 链接检测中 → `ready` 已完成但未确认 → `submitted` 已提交 → `needs_supplement` 退回补充 → `qualification_pass` 资格通过 → `reviewing` 评审中 → `shortlisted` 入围 → `winner` 获奖 / `not_selected` 未入选 / `withdrawn` 撤回 / `invalid` 作废。

每次迁移记录操作者、原因、时间、来源 IP、请求 ID。非法迁移返回 `409 STATE_CONFLICT`，不能通过前端隐藏按钮绕过。

## 5. 功能需求

### AUTH 账号与会话

- 注册时校验邮箱/手机号唯一性，发送一次性验证链接或验证码。
- 登录、退出、忘记密码、重置密码、登录失败限速；错误提示不泄露账号是否存在。
- 使用服务端会话 Cookie，不把长期令牌放进 `localStorage`；Cookie 设置 `HttpOnly`、`Secure`、合适的 `SameSite` 和过期时间。
- 管理员、评审账号强制 MFA；优先预留 Passkey/WebAuthn，无法一期落地时采用 TOTP 并记录恢复码。

### PROFILE 参赛者与团队

- 个人信息：姓名、联系方式、地区、是否学生、学校、专业、指导教师。
- 团队信息：团队名称、联系人、成员列表、成员授权声明。
- 修改敏感资料需要重新认证；变更留痕。

### SUBMISSION 投稿编辑

- 分步表单：方向与形式 → 主体作品链接 → 制作解析链接 → 导览与体验链接 → 权利与 AI 披露 → 确认提交。
- 自动保存草稿，离开页面前提示未保存内容。
- 所有必填项、必填链接预检和声明完成后才允许提交；提交前展示只读摘要、每条预检结果和声明勾选。
- 生成唯一回执编号、提交时间和版本号；向参赛者展示可下载回执。

### LINK-CHECK 外部视频链接预检

- 每条视频链接按用途保存：`mainWork`（必填，2—10 分钟）、`makingOf`（必填，不超过 1 分钟）、`guideVideo`（VR/交互/实时作品必填，1—5 分钟）和 `experience`（可选）。
- 后端仅接受 HTTPS、组委会配置白名单内的平台 URL；拒绝 URL 用户信息、非标准端口、字面量 IP、私网/保留地址、未允许重定向及无法标准化的 URL。
- 检测 Worker 仅可通过网络隔离的出网通道访问已批准的平台适配器/API；解析 DNS 后再次拦截内网地址，限制请求方法、响应大小、超时和重试。禁止通用网页抓取或把第三方原始响应返回浏览器。
- 适配器只返回安全化的可访问性、平台标识、外部视频 ID、时长和分辨率。平台不能可靠提供必需元数据时，结果为“不可核验”，不是“通过”。
- 预检失败必须返回稳定错误码与可读规则，例如 `MAIN_DURATION_OUT_OF_RANGE`、`VIDEO_PRIVATE_OR_LOGIN_REQUIRED`、`RESOLUTION_TOO_LOW`、`METADATA_UNAVAILABLE`；前端按用途定位失败项。检测和重试均幂等并限流。

### REVIEW 评审与反馈

- 资格审查：通过、退回补充、作废，并填写结构化原因。
- 评分维度固定为：主题契合度 20、视觉表现力 30、技术创新性 20、叙事/概念深度 30。
- 评审可保存未提交草稿；提交后按策略锁定或仅允许管理员解锁并记录原因。
- 参赛者只能看到面向自己的反馈，不可看到其他评审身份和内部备注。

### ADMIN 管理后台

- 仪表盘：总数、各状态、链接检测失败、待审、异常告警。
- 作品列表支持编号、方向、作者、状态、时间、版本筛选；默认分页，禁止一次性加载全量。
- 详情页展示结构化信息、链接预检元数据、版本时间线、审计事件、评分和反馈。
- 打开外部链接前二次确认并记录理由；后端返回已核验的规范化 URL；导出采用异步任务并限制字段。
- 赛事配置（截止/展映时间、主题、会场、方向、公开文案、品牌组件资产、大小限制、评分权重）变更需超级管理员权限并写审计。

## 6. 数据模型（逻辑层）

- `users`：账号、密码哈希、验证状态、MFA 状态、最后登录信息、软删除标记。
- `roles` / `user_roles`：角色及权限映射。
- `teams` / `team_members`：团队资料和成员关系。
- `submissions`：作品业务主键、回执号、方向、形式、当前状态、当前版本。
- `submission_versions`：每次提交的不可变快照、声明、AI 披露、权利声明、提交时间。
- `media_links`：链接用途、原始/规范化 URL、平台、外部视频 ID、可访问性、时长、分辨率、预检状态/错误码、检测时间、版本归属。
- `reviews`：评审人、各维度分数、总分、评语、提交时间、版本号。
- `feedback`：面向参赛者的退回原因、补充要求、发布状态。
- `notifications`：站内通知及发送状态；邮件/短信只存必要投递元数据。
- `audit_logs`：操作者、动作、对象、结果、原因、IP、User-Agent、requestId、时间。
- `settings`：可版本化赛事配置，包含截止/展映节点、主题、会场、公开文案、品牌组件资产映射、链接规则和允许平台；敏感配置只存密钥管理系统引用。

关键约束：业务表使用 UUID/不可猜测 ID；回执编号单独唯一；`submission_versions` 和 `media_links` 通过外键保护；删除采用软删除或保留策略，不物理删除审计证据。

## 7. API 合同（建议 `/api/v1`）

### 7.1 通用约定

- 请求和响应使用 JSON；本站不接收视频二进制内容。
- 成功响应包含 `requestId`；错误统一为 `{ code, message, details?, requestId }`。
- 列表使用 cursor 分页，响应包含 `items` 与 `nextCursor`。
- 创建提交、发起链接预检、正式提交、状态迁移支持 `Idempotency-Key`。
- 认证失败返回 `401`，权限不足返回 `403`，状态冲突 `409`，参数错误 `422`，限流 `429`，未知异常 `500`；不要把堆栈返回前端。

### 7.2 核心资源

| 方法 | 路径 | 用途 | 权限 |
| --- | --- | --- | --- |
| POST | `/auth/register` | 注册并发起验证 | 公开 |
| POST | `/auth/login` | 登录并建立会话 | 公开 |
| POST | `/auth/logout` | 注销当前会话 | 已登录 |
| POST | `/auth/password-reset` | 申请/确认重置 | 公开/一次性令牌 |
| GET | `/me` | 当前用户与角色 | 已登录 |
| POST | `/submissions` | 创建草稿 | 参赛者 |
| GET/PATCH | `/submissions/:id` | 查看/编辑草稿 | 对象所有者/管理员 |
| POST | `/submissions/:id/media-links` | 新增或更新作品链接 | 对象所有者 |
| POST | `/submissions/:id/media-links/:linkId/prechecks` | 发起或重试链接预检 | 对象所有者 |
| GET | `/submissions/:id/media-links/:linkId/precheck` | 查询安全化预检结果 | 对象所有者/授权管理员 |
| POST | `/submissions/:id/submit` | 提交不可变版本 | 对象所有者 |
| GET | `/submissions/:id/timeline` | 查看状态与版本 | 所有者/授权管理员 |
| POST | `/admin/submissions/:id/transitions` | 审查/退回/作废 | 管理员 |
| POST | `/admin/submissions/:id/media-links/:linkId/open` | 记录后返回已核验外部链接 | 管理员/授权评审 |
| GET/POST/PATCH | `/admin/submissions/:id/reviews` | 评分与评语 | 分配评审/管理员 |
| GET | `/admin/audit-logs` | 查询审计日志 | 超级管理员 |

API 不返回未核验的原始链接或第三方原始响应。所有对象接口都做对象级授权，不能仅依赖前端传来的用户 ID。

## 8. 安全与可靠性基线

设计依据包括 NIST SP 800-63B-4、OWASP Authentication/Password Storage/MFA/SSRF Cheat Sheets，以及 CISA 关于管理员优先采用抗钓鱼 MFA、最小权限和会话期限的建议。密码使用 Argon2id（参数经压测确定，至少满足 OWASP 当前下限），允许长密码和 Unicode，不强制脆弱的字符组合规则；密码不明文、不可逆加密、不写日志。

- 全站 HTTPS，强制 HSTS；反向代理、应用、数据库和链接检测 Worker 分离权限。
- 会话轮换、防固定、防 CSRF；登录、重置密码、链接创建/检测和外部链接打开接口限速并告警。
- 管理端和评审端最小权限、MFA、短会话；敏感操作要求重新认证。
- 外部链接预检采用严格平台白名单、安全 URL 解析、禁用或逐跳重验重定向、DNS/IP 双重检查、隔离出网和响应上限；不得把通用 URL 请求器暴露给用户输入。
- 数据库字段分级；联系方式等敏感字段加密或脱敏展示；生产日志禁止正文、密码、令牌和签名 URL。
- 每日备份数据库和链接预检元数据；至少进行一次恢复演练并记录 RPO/RTO。
- 应用、数据库、链接检测 Worker、日志、备份使用独立命名空间/账号/端口/目录和出网策略，不修改服务器其他项目的配置。

## 9. 部署与运行方案

推荐以独立容器或独立 systemd 服务运行：独立环境变量、数据库 schema/实例、链接检测 Worker、日志目录、健康检查、端口和最小化出网策略；由现有反向代理仅转发本项目域名。生产密钥由服务器密钥管理或受限环境变量注入，不进仓库。发布采用迁移前备份、灰度/回滚包、健康检查和数据库迁移回滚预案。

## 10. 垂直切片与实现顺序

1. **Slice A：账号闭环**——注册、登录、会话、角色、审计、管理员 MFA。
2. **Slice B：草稿闭环**——个人/团队资料、六步表单、自动保存、回执编号。
3. **Slice C：链接预检闭环**——平台白名单、隔离检测、元数据适配、逐条失败反馈、幂等重试。
4. **Slice D：提交闭环**——声明确认、不可变版本、状态机、通知。
5. **Slice E：管理闭环**——检索、资格审查、受控打开外部链接、退回补充。
6. **Slice F：评审闭环**——分配、评分、反馈、导出、审计和统计。
7. **Slice G：上线闭环**——备份恢复、限流告警、可访问性、跨浏览器和安全验证。

## 11. 验收标准

### 业务验收

- 参赛者可在中断后继续草稿和链接检测；刷新、重复点击、超时重试不会产生重复版本或重复检测副作用。
- 不满足必填项、允许平台、公开可访问、时长、分辨率、权利声明或链接预检条件时，提交按钮不可用且服务端仍拒绝请求，并逐条返回不合格规则。
- 退回补充会创建新版本，旧版本和原始审计记录可查询。
- 管理员/评审只能在授权作品详情中打开已核验链接；评审只能看分配作品；参赛者无法访问他人对象。
- 评分权重和总分计算可复核，修改评审结果有原因和审计记录。

### 技术与安全验收

- 单元、集成、端到端测试覆盖状态迁移、对象授权、幂等、限流、CSRF、链接预检绕过、SSRF 和安全化外部链接打开。
- 使用私网 IP、DNS 重绑定、未允许重定向、伪造平台 URL、登录可见视频、超时响应、缺失元数据和越权 ID 测试均失败并留下安全日志。
- 100 名模拟用户并行登录、草稿保存和链接检测时，错误率、超时和恢复行为达到项目约定阈值（上线前填写具体 SLO）。
- 备份可恢复到新环境；部署不影响同机其他项目；监控能发现数据库、链接检测队列和出网策略异常。
- 键盘可操作、焦点可见、错误与状态有文本表达，移动端 375px 宽度不出现横向滚动。

## 12. 开发前核实机制

所有外部依赖、赛事正式规则和部署资源问题统一维护在《待核实问题清单》。该清单是开发启动门槛：开发前一次性确认；设计阶段可按建议默认值继续。任何新增的非阻塞待确认问题必须先登记，不单独要求用户即时答复。

- [CISA Require Multifactor Authentication](https://www.cisa.gov/audiences/small-and-medium-sized-businesses/secure-your-business/require-multifactor-authentication)：优先保护管理员和高价值账户，并规划抗钓鱼 MFA。
- [OWASP API7:2023 Server Side Request Forgery](https://api-security.owasp.org/editions/2023/en/0xa7-server-side-request-forgery/)：用户提供的 URL 获取功能是 SSRF 攻击面，应使用来源、协议和端口白名单、禁用重定向并隔离请求器。
- [OWASP SSRF Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)：URL 与 DNS 校验需结合网络层私网拦截，防范 DNS 重绑定和内部服务访问。

截至 2026-09-22，外部链接预检的可执行结论是：将 URL 检测视为不可信输入处理，而不是普通网页抓取；仅支持经配置的公共视频平台适配器，不能可靠验证时即失败。实现技术栈尚未冻结；开发时须锁定 HTTP 客户端及依赖版本并复核其安全公告。
