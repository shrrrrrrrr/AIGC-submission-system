# 数据库迁移说明

迁移按编号顺序执行。生产执行前必须：

1. 确认目标 PostgreSQL 主版本和独立数据库/账号。
2. 完成逻辑备份并记录备份校验值。
3. 在隔离测试库按顺序执行 `001_auth.up.sql`、`002_mfa_credentials.up.sql`、`003_submissions.up.sql`，验证约束、索引和各自回滚脚本。
4. 观察连接数、锁等待和迁移耗时；超出预设窗口立即停止。
5. 迁移失败时先恢复备份或执行经过验证的 down 脚本，不在生产手工改表。

`002_mfa_credentials.up.sql` 为已存在用户表增加 MFA 待确认密文和最近已用 TOTP 计数器；该迁移只增加可空列，回滚时先确认没有依赖这些列的应用版本。应用已具备 PostgreSQL 认证与投稿仓储及生产启动接线，但开发入口仍使用内存仓储；在正式邮件适配器、迁移演练和真实数据库集成测试完成前，生产启动保护不会解除。

`003_submissions.up.sql` 建立投稿逻辑主表、版本快照、外部媒体链接和幂等键表。草稿可编辑，版本快照和媒体链接使用 `RESTRICT` 外键保留历史证据；正式提交服务接入前，不要把 `current_status` 当作可由客户端直接修改的字段。
